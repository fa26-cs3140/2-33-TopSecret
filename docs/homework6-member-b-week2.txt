IMPLEMENTED CONTROLLER REQUIREMENTS

1. No arguments start the terminal. Exactly -web starts the JDK HTTP server on
   localhost:3002. --change-password still works. Other arguments show usage.
2. GET / shows a username/password form. POST /login uses the existing ciphered
   credential store. Bad credentials return 401 and no cookie; initial passwords
   must be established from the terminal. No web account creation is provided.
3. Valid login returns 303 /menu and TopSecretSession with an unpredictable
   32-byte random token, Path=/, HttpOnly and SameSite=Lax. Login omits Max-Age and
   Expires, making it a browser-session cookie. Browser session restore behavior
   is browser-controlled; the server cannot detect the browser closing.
4. Tokens are held only in a concurrency-safe in-memory store. Logout clears the
   cookie and token. Re-login replaces the presented token. Separate clients have
   independent tokens. Shutdown/restart clears every session.
5. Every application route requires a valid token before reading model data.
   Account/role resolution happens on every protected data request. Audit remains
   administrator-only, including after promotion/demotion during an active session.
6. Missing/invalid accounts prevent startup before binding. The user is directed
   to terminal setup. Failure to bind or validate accounts does not start a server.
7. ContentMenu and HttpWebServer share ContentController for list/read/audit and
   ContentText for displayed record/audit text. HTTP does not invoke Scanner loops.
8. All existing production classes now reside in model, view or controller, except
   TopSecret, the small executable composition root. Tests were migrated to retain
   package-scoped model test access. The executable Main-Class remains TopSecret.

ROUTES AND ERRORS

  GET  /          login form; authenticated users redirect to /menu
  POST /login     form login; username/password decoded as UTF-8
  GET  /menu      protected links to the four content types and permitted audit
  GET  /content   protected list; type=briefs|agents|facilities|missions
  GET  /record    protected detail; type as above and positive integer id
  GET  /audit     protected administrator-only audit text
  POST /logout    invalidate token, expire cookie and redirect to /

Missing/forged sessions redirect to /. Invalid input returns 400, unauthorized
audit access 403, unknown authenticated pages/missing records 404, unsupported
methods 405 with Allow, oversized login forms 413 and backend failures a generic
500. Malformed/duplicate parameters are rejected. Request failures do not stop
the server. No web content mutations or account management routes exist.
Responses use UTF-8, Cache-Control:no-store and a restrictive CSP. Dynamic content
is escaped. Application pages contain plain HTML without CSS or JavaScript.
