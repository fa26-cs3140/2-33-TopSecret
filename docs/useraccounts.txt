User Accounts

Top Secret supports multiple accounts. Credentials and roles are stored in the
ciphered credential file, never in SQLite.


RULES

  Username    at least 3 characters; letters, numbers, hyphens and underscores;
              case-sensitive and unique
  Password    at least 5 characters with uppercase and lowercase letters;
              tab characters are prohibited


ACCOUNT LIFECYCLE

  Initial startup
    With no accounts, the application prompts for a username and password,
    creates the first account as ADMIN and starts its session.

  Normal startup
    The application requests username and password. Unknown users and incorrect
    passwords end the attempt with "Login failed."

  Account creation
    An administrator calls AuthenticationService.createUser(username). The new
    STANDARD account initially has no password.

  First login
    The new account owner chooses and confirms a password before login completes.

  Password change
    `./gradlew run --args="--change-password"` verifies the current password and
    confirms the replacement before updating that account.


STORAGE FORMAT

data/credentials.cip contains one ciphered account per line. Before encryption,
each line is:

  username TAB password TAB role

An empty password marks an account awaiting its first login. Role values are
ADMIN and STANDARD. Two-field records without a role are accepted as STANDARD
for backward compatibility. The credential file is generated and not committed.

If a credential file uses an incompatible account format, remove it only when its
accounts are no longer needed; the next startup will create a new initial account.


COMPONENTS

  Credential              username, password and role value
  CredentialStore         existence, read-all and write-all boundary
  FileCredentialStore     ciphered-file implementation
  AuthenticationService   validation, login, account creation, password changes,
                          sessions and role changes
  TopSecret               startup, login and password-change orchestration

Tests cover validation, multiple accounts, passwordless accounts, malformed data,
cipher failures, mock-store interactions, startup flows and real temporary files.
