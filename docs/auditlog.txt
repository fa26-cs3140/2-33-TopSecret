auditlog.txt - Member D

The audit log records who read or created an item, which item, and when. It is
stored in the same SQLite database as the content (data/missions.db).


TABLE

  CREATE TABLE IF NOT EXISTS audit_log (
      id           INTEGER PRIMARY KEY AUTOINCREMENT,
      event_type   TEXT NOT NULL,
      content_type TEXT NOT NULL,
      content_id   INTEGER NOT NULL,
      username     TEXT NOT NULL,
      timestamp    TEXT NOT NULL
  );

  +--------------+---------+----------+--------------------------------------+
  | column       | type    | nullable | notes                                |
  +--------------+---------+----------+--------------------------------------+
  | id           | INTEGER | no       | PK, AUTOINCREMENT                    |
  | event_type   | TEXT    | no       | READ or CREATE                       |
  | content_type | TEXT    | no       | BRIEF, AGENT or FACILITY             |
  | content_id   | INTEGER | no       | id of the item in its own table      |
  | username     | TEXT    | no       | who did it                           |
  | timestamp    | TEXT    | no       | ISO 8601 local date-time             |
  +--------------+---------+----------+--------------------------------------+

  No foreign keys. content_id points into one of three tables depending on
  content_type, usernames live in the credential file rather than SQLite, and
  the log must still describe an item after it is deleted.


CLASSES

  AuditEventType       READ, CREATE
  AuditContentType     BRIEF, AGENT, FACILITY
  AuditLogEntry        one row: id, event type, content type, content id,
                       username, timestamp. The id is 0 until saved.
  AuditLogRepository   record(entry), record(event, type, id, username) which
                       stamps the current time, and getAllEntries() newest
                       first.
  SqliteAuditLogRepository
                       the SQLite implementation. initialize() creates the
                       table and is safe to run every start; TopSecret.main
                       calls it next to the mission repository. A connection
                       is opened per call, like SqliteMissionRepository.
  AuditLogException    any failure, with a message for the user. SQLException
                       never escapes the repository.


HOW TO USE IT

  After a successful read or create of an item:
      auditLog.record(AuditEventType.READ, AuditContentType.BRIEF, id, username);
  To show the log:
      List<AuditLogEntry> entries = auditLog.getAllEntries();

  Failed operations are not logged, and viewing the log is not logged.
