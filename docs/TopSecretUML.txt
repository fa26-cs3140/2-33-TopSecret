Responsibility boundaries
- A handles command-line input and displayed output.
- B coordinates requests without directly accessing files or deciphering text.
- C owns all filesystem access and returns safe failure values.
- D validates key data and deciphers mission text without direct file access.

HOMEWORK 4 DATABASE (Member A)

 The missions table holds one row per Mission. Briefs are plain text, not
 ciphered. Credentials are never stored here. Full schema: docs/database.txt

  +---------------------------------------------------+
  |                     missions                      |
  +-------+---------+---------------------------------+
  | id    | INTEGER | PK, AUTOINCREMENT               |
  | title | TEXT    | not null                        |
  | brief | TEXT    | not null, plain text, searched  |
  | date  | TEXT    | not null, ISO 8601              |
  +-------+---------+---------------------------------+

 Startup wiring built in TopSecret.main:

  +--------------------------+
  | SqliteMissionRepository  |  one instance, shared
  +------------+-------------+
          |            |
          | passed to  | passed to
          v            v
  +------------------+   +--------------------------+
  | MissionSearch-   |   | ProgramControlImpl       |
  | Service (C)      |-->| + listMissions()         |
  |                  |   | + searchMissions(query)  |
  +------------------+   +--------------------------+

 Both read the same database, so a search and a list never disagree.

Homework 4 responsibility boundaries
- Member A owns SqliteMissionRepository, all database connections, the schema,
  and the TSV import. No other class touches java.sql or the database file.
- Member B completes login before the interactive menu is shown.
- Member C owns MissionSearchService and its unit/integration tests.
- Member D calls ProgramControl.searchMissions and displays the results.
