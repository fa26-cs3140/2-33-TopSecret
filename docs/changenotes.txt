Top Secret - Release Snapshot

Current as of October 23, 2026.


CURRENT CAPABILITIES

- Authenticated, persistent command-line sessions.
- Multiple accounts with ADMIN and STANDARD roles.
- Ciphered credential storage kept separate from operational data.
- Browsing and reading briefs, agents and facilities by stable database ID.
- Administrator-only content creation and account/role management.
- SQLite persistence for missions, content, relationships and audit events.
- Case-insensitive mission-brief search through the retained mission API.
- Successful READ and CREATE audit events associated with the acting username.


CURRENT DATA MODEL

Brief, Agent, Facility and MissionAssignment are immutable domain objects.
SqliteContentService imports facilities.tsv and agents.tsv transactionally,
normalizes dates to ISO text, and deterministically creates relationships for
sample missions. Each mission has exactly one facility mapping and at least one
unique agent mapping.

Foreign keys restrict deletion of referenced agents and facilities. Protective
triggers reject direct removal of a mission's required facility mapping or final
agent mapping. Deleting a mission cascades its relationship rows.

ContentService exposes list, read, add, update and delete operations. Mutations
require an administrator session. Creation and its CREATE audit entry share a
transaction, so an audit failure rolls back the content row.


COMPATIBILITY SURFACE

The original numbered-file command API, ProgramControl abstraction and mission
search API remain available and tested. The production entry point uses the
authenticated ContentMenu. The briefs table is intentionally separate from the
searchable missions table.


QUALITY STATUS

The current suite contains 380 JUnit tests across 38 test classes. It includes
unit tests, temporary SQLite integration tests, real seed imports, access-control
checks, transaction rollback, restart idempotency, command-line interaction and
credential/cipher persistence. `./gradlew clean check jar` compiles, tests,
verifies the configured JaCoCo method-coverage gate and builds the executable jar.

The current architecture is documented in SystemClasses.pdf and DatabaseERD.pdf.
