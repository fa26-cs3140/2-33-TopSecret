CURRENT CAPABILITIES

- Authenticated, persistent command-line sessions.
- Multiple accounts with ADMIN and STANDARD roles.
- Ciphered credential storage kept separate from operational data.
- Browsing and reading briefs, agents and facilities by stable database ID.
- Administrator-only content creation, updates and account/role management.
- SQLite persistence for missions, content, relationships, audit events and messages.
- Case-insensitive mission-brief search through the retained mission API.
- Successful READ, CREATE and UPDATE audit events associated with the acting username.
- Any logged-in user can leave a message for an agent. The user whose username
  matches that agent's name (case insensitive) can read it; nobody else can.


CURRENT DATA MODEL

Brief, Agent, Facility, MissionAssignment and Message are immutable domain objects.
SqliteContentService imports facilities.tsv and agents.tsv transactionally,
normalizes dates to ISO text, and deterministically creates relationships for
sample missions. Each mission has exactly one facility mapping and at least one
unique agent mapping.

Foreign keys restrict deletion of referenced agents and facilities. Protective
triggers reject direct removal of a mission's required facility mapping or final
agent mapping. Deleting a mission cascades its relationship rows.

ContentService exposes list, read, add, update and delete operations. Mutations
require an administrator session. Creation and update each share a transaction with
their audit entry, so an audit failure rolls back the content change.

A message belongs to one agent through messages.agent_id. SqliteMessageService
stores the sender (the session's username) and the time with each message. Its
inbox query joins messages to agents and matches the agent's name to the session's
username ignoring case. Messages are not a ContentType and are not audited.
Deleting an agent would cascade to its messages; agent delete is not exposed
through the menu.


COMPATIBILITY SURFACE

The original numbered-file command API, ProgramControl abstraction and mission
search API remain available and tested. The production entry point uses the
authenticated ContentMenu. The briefs table is intentionally separate from the
searchable missions table. The older ContentMenu and UserInterface constructors
still work and simply offer no message options.


QUALITY STATUS

the explicitly disabled web-server drafts. It includes unit tests, temporary SQLite
integration tests, real seed imports, access-control checks, transaction rollback,
restart idempotency, command-line interaction, messaging against a real seeded
database and credential/cipher persistence. `./gradlew clean check jar` compiles,

executable jar. These counts are for the hw6-member-d branch and will change as the
other members' week 2 work is merged.
