Wireframe 4: Access and request errors

Top Secret web view

Request outcomes

  • Missing, forged or revoked server session: 303 /
  • Invalid form, duplicate parameter or nonpositive ID: 400
  • Standard user requesting audit: 403
  • Unknown authenticated page or missing record: 404
  • Wrong route method: 405 + Allow; admin create/edit use dedicated forms
  • Oversized login or editing form: 413
  • Storage failure: generic 500; server continues serving

No passwords, tokens or backend details appear in error pages.

Application HTML uses forms, lists, links and tables. No JavaScript or images. Shared styling and navigation are delivered.

TypeFields / choices

Agentname, date_of_birth, optional date_of_death, optional notes, facility choice
Facilityname, abbreviation; country choice, supplied by the countries type
Missiontitle, brief, date; facility and first-agent choices required on create
Countryname; an ordinary content type

New scalar values start empty; relationship choices start unselected. Edit loads current values. Store IDs behind relationship labels; escape all labels, values and error text. Long text uses textareas; dates use date inputs. Mission update edits scalar fields only.

  • Missing/invalid session: 303 to login.
  • Current standard role: 403 on all editing routes, including crafted POST.
  • Bad fields, duplicate/unexpected parameters or invalid CSRF: 400, no mutation.
  • Missing record: 404. Wrong method: 405 + Allow. Oversized body: 413.
  • Unexpected storage failure: generic 500; no database details.

Account creation, passwords and role management remain terminal-only. C's messaging is available. Countries and styling are delivered. Session administration remains a team dependency.

Homework 7: Compose and send

Member C. Messaging requires a valid session but does not require administrator permission.

Top Secret | briefs | agents | facilities | missions | countries | Messaging | [Log out]

GET /messages/new - New message

To: [Select an agent v] - options come from the current agents table.

Message: [multiline text area, up to 4096 characters]

[Send message]   [Cancel]

POST /messages/send checks recipient, nonblank text, size, form fields and CSRF token, then redirects to /messages. The sender is the session username, not a form field.

Blank text or an unknown recipient returns a safe error; malformed or forged input cannot create a message. A standard user sees the same compose form as an administrator.

All dynamic text is escaped. Shared CSS and navigation come from HtmlView.shell. No JavaScript or images.
