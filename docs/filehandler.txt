File Handling

FileHandlerImpl owns direct access to encrypted record files, cipher keys and text
seed files. Other components depend on FileHandler rather than the filesystem.


LOCATIONS AND SELECTION

- Encrypted .cip files reside in data/ and are sorted alphabetically.
- Cipher keys reside in ciphers/; key.txt is the default.
- Text seed files are resolved from the project root.
- UTF-8 content is preserved.
- Symbolic links are not treated as readable files.
- Normalized key paths must remain inside ciphers/.


INTERFACE CONTRACT

  getFileList()
    Returns newline-separated .cip filenames, or an empty string when no readable
    files are available.

  readFile(fileNumber)
    Uses one-based numbering from getFileList and returns complete contents, or
    null for an invalid, missing or unreadable selection.

  readKey(keyFileName)
    Reads the selected key, using key.txt when the name is null. Returns null when
    the key cannot be read or the path would escape ciphers/.

  readText(relativePath)
    Reads UTF-8 seed data through the shared project-root resolution policy.

Filesystem errors are converted into empty or null results. Higher layers translate
those results into domain-specific messages. Tests cover sorting, numbering,
content preservation, missing paths, alternate keys and path traversal.
